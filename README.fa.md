# Faktorito

Faktorito یک پلتفرم **مدیریت عضویت و صدور فاکتور** برای **باشگاه‌ها** است (تمرکز اصلی روی باشگاه‌ها).
ساخته‌شده با **Node.js، Express 5، MongoDB، EJS**.

## امکانات

### مدیریت اعضا
* ثبت عضو با کد عضویت خودکار (`M-0001`, ...)، شماره تلفن (با اعتبارسنجی و پشتیبانی از ارقام فارسی) و یادداشت
* وضعیت عضو: فعال / منجمد / غیرفعال
* جستجو و فیلتر (فعال، رو به پایان، منقضی، منجمد، غیرفعال) + خروجی CSV
* صفحه‌ی جزئیات هر عضو: تاریخچه فاکتورها، مجموع پرداخت، روزهای باقی‌مانده

### فاکتور مخصوص هر عضو
* ساخت فاکتور مستقیماً برای یک عضو (جستجوی لحظه‌ای عضو، یا `/invoices/new?member=<id>`)
* ثبت عضو جدید همزمان با صدور فاکتور
* فاکتور اسنپ‌شات نام/تلفن عضو را نگه می‌دارد؛ ویرایش بعدی عضو فاکتورهای قدیمی را تغییر نمی‌دهد
* **با تأیید پرداخت، اشتراک عضو خودکار تمدید می‌شود** (تمدید زودهنگام روی زمان باقی‌مانده اضافه می‌شود)
* پلن‌ها (فقط نام و قیمت)، آیتم‌های اضافه (نوشیدنی، مکمل ...)، تخفیف درصدی/ثابت، فروش متفرقه بدون پلن
* لینک عمومی غیرقابل‌حدس فاکتور (`/i/<publicId>`) با شماره تلفن ماسک‌شده + دانلود تصویر
* خروجی CSV فاکتورها

### داشبورد
* تعداد اعضای فعال / رو به پایان / منقضی، درآمد ماه جاری، مجموع مطالبات معوق
* لیست اعضایی که اشتراکشان به‌زودی تمام می‌شود

### احراز هویت و دسترسی
* Session (ذخیره در MongoDB) + RBAC/PBAC، تعلیق/غیرفعال‌سازی حساب، ابطال نشست بعد از تغییر رمز

## حساب‌ها و پنل‌ها
یک سیستم ثبت‌نام و ورود برای همه وجود دارد: `/register` و `/login`. هر کس بعد از ورود به پنل مخصوص نقش خودش می‌رود.

| نقش | پنل | دسترسی |
|---|---|---|
| کاربر عادی (`member`) | `/me` | عضویت و فاکتورهای خودش، اعلان‌های باشگاه، خروج از باشگاه |
| صاحب کسب‌وکار (`owner`) | `/dashboard` | اعضا، پلن‌ها، فاکتورها، صدور خودکار، اعلان‌ها، برندینگ |
| ادمین (`admin`) | `/admin` | بررسی کاربران/فاکتورها، تعلیق، بررسی درخواست حذف حساب |
| مدیر ارشد (`moderator`) | `/admin` | همه‌ی دسترسی‌های ادمین + تغییر نقش و حذف؛ از UI قابل واگذاری نیست |

* **ساخت باشگاه** فقط از مسیر `/gym/create` (از داخل پنل کاربر) انجام می‌شود: کاربر عادی شرایط ویژه را می‌پذیرد، نام کسب‌وکار را وارد می‌کند و حسابش به `owner` ارتقا می‌یابد.
* **صاحب کسب‌وکار نمی‌تواند عضو باشگاه دیگری باشد و عضو یک باشگاه نمی‌تواند کسب‌وکار بسازد** (در ساخت، افزودن عضو و تغییر نقش توسط ادمین بررسی می‌شود).
* ماتریس دسترسی‌ها در `src/config/permissions.js` متمرکز است و هیچ‌کس روی کاربری با رتبه‌ی برابر یا بالاتر عمل نمی‌کند.

### عضویت در باشگاه
* کاربر عادی به‌صورت پیش‌فرض عضو هیچ باشگاهی نیست.
* وقتی مدیر باشگاه عضوی را با ایمیل یک حساب تأییدشده اضافه کند، در پنل آن کاربر نوشته می‌شود «شما عضو این باشگاه هستید» و اعلان لحظه‌ای می‌گیرد.
* هر حساب **هم‌زمان فقط عضو یک باشگاه** است (ایندکس یکتای جزئی روی `Member.account`). باشگاه دیگر نمی‌تواند او را اضافه کند تا وقتی که خودش «خروج از باشگاه» را بزند یا مدیر باشگاه حذفش کند.
* حذف عضو توسط مدیر نرم است (`deletedAt`، با امکان بازیابی) و حساب را آزاد می‌کند.

## پلن‌ها، دوره‌ی اشتراک و صدور خودکار
* **پلن زمان ندارد**: فقط نام، قیمت و توضیح دارد.
* «دوره‌ی اشتراک» روی **خود فاکتور** انتخاب می‌شود (بدون تمدید / 1 / 2 / 3 / 4 / 6 / 12 ماه) و با ثبت پرداخت، اشتراک عضو به همان اندازه تمدید می‌شود.
* **صدور خودکار** (`/auto-invoices` و کارت «صدور خودکار» در صفحه‌ی هر عضو): مدیر برای یک عضو تنظیم می‌کند «هر ماه / هر 3 ماه (1، 2، 3، 4، 6، 12) با این پلن و این یادداشت فاکتور صادر شود». هر زمان می‌تواند پلن، بازه یا تاریخ را عوض کند، متوقف کند، همین حالا صادر کند یا حذف کند.
* تاریخ‌ها از نقطه‌ی شروع حساب می‌شوند (31 ژانویه، 28 فوریه، 31 مارس)؛ بعد از خاموشی طولانی فقط یک فاکتور صادر می‌شود و «صدور همین حالا» دوره‌ی بعدی را دوباره صادر نمی‌کند. عضو منجمد یا فاکتور پرداخت‌نشده‌ی قبلی، دوره را رد می‌کند.

## اعلان‌های باشگاه
مدیر باشگاه از `/announcements` اعلان می‌گذارد (پیش‌فرض 24 ساعت؛ 1 ساعت تا 7 روز). اعلان در پنل `/me` همه‌ی اعضا دیده می‌شود و برای اعضای آنلاین از طریق Socket.IO لحظه‌ای می‌رسد.

## ورود و حساب کاربری (Nodemailer)
* ثبت‌نام (با پذیرش شرایط) و بعد کد OTP شش‌رقمی به ایمیل (اعتبار 10 دقیقه، حداکثر 5 تلاش اشتباه، 1 کد در دقیقه، 5 کد در ساعت)
* اگر کاربر تأیید نکرد و بعداً وارد شد، به `/auth/verify` هدایت می‌شود و کد تازه می‌گیرد
* ورود با رمز، ورود بدون رمز با کد ایمیلی (`/auth/login/otp`)، فراموشی رمز (`/auth/forgot` و بعد `/auth/reset`)
* درخواست حذف حساب: حساب فوراً غیرفعال می‌شود (`pending_deletion`) و ادمین بررسی می‌کند؛ کاربر می‌تواند از `/auth/cancel-deletion` لغو کند
* **فقط کد یک‌بارمصرف (OTP) ایمیل می‌شود** (تأیید ثبت‌نام، ورود با کد، بازیابی رمز، تغییر ایمیل)؛ فاکتور، یادآوری و بقیه‌ی رویدادها فقط درون خود سایت (اعلان + Socket.IO) هستند. در `mailer.js` تابع ارسال عمومی وجود ندارد.
* ارسال با **Gmail**: `GMAIL_USER` (آدرس) و `GMAIL_PASSWORD` (باید «رمز برنامه» / App Password گوگل باشد، نه رمز عادی حساب؛ نیاز به تأیید دومرحله‌ای). بدون این دو، کدها در حالت توسعه در کنسول چاپ می‌شوند و در production برنامه بالا نمی‌آید.
* **سقف سراسری: 150 ایمیل در روز برای کل سرویس** (نه برای هر کاربر)، با شمارنده‌ی اتمیک در MongoDB (`DailyQuota`، روز به وقت `QUOTA_TIMEZONE`، پیش‌فرض تهران). ایمیلی که ارسالش شکست بخورد از سقف کم نمی‌کند. با پر شدن سقف، درخواست کد پیام «ظرفیت امروز تکمیل شده» می‌گیرد.
* **سقف ثبت‌نام: 25 نفر در روز برای کل سرویس**، تا ایمیل Gmail الکی خرج نشود و از سقف ارسال گوگل بیشتر نشود. نفر 26 با خطای 429 و هدر `Retry-After` پیام «فردا دوباره تلاش کنید» می‌گیرد و صفحه‌ی ثبت‌نام هم از قبل پر بودن ظرفیت را نشان می‌دهد و دکمه را غیرفعال می‌کند. ثبت‌نام تکراری یا ناموفق از سقف کم نمی‌کند.

## زمان واقعی (Socket.IO)
* یک اتصال سوکت برای هر صفحه (`public/realtime.js`)، روی همان Session اکسپرس؛ هر کاربر فقط در اتاق خودش است، حساب مسدود یا ورود‌نکرده وصل نمی‌شود و Origin بررسی می‌شود.
* **اعلان‌ها خودکار «خوانده» می‌شوند**: وقتی پنل زنگوله باز باشد، تب دیده شود و یک اعلان حدود 1٫2 ثانیه در دید باشد، خوانده حساب می‌شود (IntersectionObserver). اعلانی که اسکرول شد و رفت یا در تب پنهان رسید خوانده نمی‌شود. کلیک روی اعلان فوراً می‌خواند؛ دکمه‌ی «خواندن همه» هم هست. خواندن بین تب‌ها و دستگاه‌ها همگام می‌شود.
* **صفحه‌ها زنده به‌روز می‌شوند** بدون رفرش: رویداد `live` با «موضوع» (`invoices`، `members`، `dashboard`، `reports`، `announcements`، `me`) به کاربر مربوط می‌رسد و فقط بخش‌های دارای `data-live` دوباره خوانده و جایگزین می‌شوند (یا کنترل‌کننده‌ی خود صفحه در `window.fxLiveHandlers` اجرا می‌شود). وقتی دیالوگی باز است یا کاربر در یک فیلد تایپ می‌کند، به‌روزرسانی عقب می‌افتد.
* صدور/ویرایش/حذف/پرداخت فاکتور، تغییر عضو، خروج/ورود عضو و اعلان باشگاه همه رویداد زنده می‌فرستند؛ با قطع و وصل شدن اتصال، همه‌چیز دوباره همگام می‌شود و نقطه‌ی سبز کنار زنگوله وضعیت اتصال را نشان می‌دهد.
* صدور فاکتور برای عضو، ثبت پرداخت و اعلان باشگاه همچنان اعلان ذخیره‌شده هم می‌سازند.

## اشتراک اعضا
در لیست اعضا برای هر عضو «اشتراک تا (تاریخ)»، «N روز مانده» (یا «N روز از انقضا گذشته») و نوار باقی‌مانده دیده می‌شود (رنگ بر اساس وضعیت: فعال، رو به پایان، منقضی، منجمد)؛ در صفحه‌ی خود عضو هم شروع، پایان و روزهای باقی‌مانده هست.

## صفحه‌ی خطا
فقط کد وضعیت، یک پیام امن و (برای خطای سرور) کد پیگیری نمایش داده می‌شود؛ stack و پیام خام خطا هرگز (حتی در development) به مرورگر نمی‌رسد و فقط در لاگ سرور با همان کد پیگیری ثبت می‌شود. صفحه ریسپانسیو است.

## ظاهر فاکتور (بدون آپلود و بدون تنظیمات برند)
* **آواتار SVG**: برای هر صاحب کسب‌وکار به‌صورت خودکار و ثابت ساخته می‌شود (از روی شناسه‌ی او)؛ چیزی برای آپلود یا تنظیم نیست.
* **امضای دیجیتال** روی canvas کشیده می‌شود و فقط نقطه‌های خطوط به سرور می‌رود (نه تصویر)؛ سرور آن‌ها را اعتبارسنجی و به مسیر SVG امن تبدیل می‌کند.
* **پنج تم**: Aurora, Midnight, Café, Mono و **Luxe** (مشکی و طلایی، فونت سریف، قاب دوخطی؛ برای برندهای لاکچری). در تنظیمات پیش‌نمایش زنده با نام و امضای خودتان دیده می‌شود.
* **یک طرح برای همه‌جا**: صفحه‌ی اول، فاکتور عمومی و پیش‌نمایش همه از یک قالب مشترک (`views/partials/invoice-sheet*.ejs`) رندر می‌شوند، پس همیشه یک شکل‌اند. در صفحه‌ی اول می‌توان تم‌ها را زنده عوض کرد.

## امکانات باشگاه
* اعضا، پلن‌ها (نام و قیمت)، «دوره‌ی اشتراک» روی هر فاکتور، تمدید خودکار اشتراک با پرداخت، یادآوری پایان اشتراک.
* **انجماد اشتراک**: روزهای انجماد هنگام رفع انجماد به تاریخ پایان اضافه می‌شود (حداکثر 180 روز).
* **گزارش فروش** (`/reports`): درآمد روزانه 7/30/90 روز و درآمد به تفکیک پلن.
* ساخت باشگاه فقط از داخل پنل کاربر؛ ثبت‌نام و ورود برای همه یکی است.

## حقوقی و سقف‌ها
* صفحه‌های ساده‌ی `/terms`، `/privacy` و `/terms/business` و یک اطلاعیه‌ی کوکی (فقط کوکی ضروری نشست استفاده می‌شود؛ پذیرفتن در مرورگر ذخیره می‌شود). همه در ثبت‌نام شرایط و حریم خصوصی را می‌پذیرند؛ فقط کسی که کسب‌وکار می‌سازد شرایط ویژه‌ی صاحبان کسب‌وکار را هم می‌پذیرد. نسخه و زمان پذیرش روی حساب ذخیره می‌شود.
* **این متن‌ها الگوی عمومی‌اند و مشاوره‌ی حقوقی نیستند.** قبل از انتشار، متغیرهای `LEGAL_ENTITY`، `CONTACT_EMAIL`، `LEGAL_JURISDICTION`، `RETENTION_DAYS` را پر کنید و متن را یک وکیل مرور کند.
* سقف‌های صاحب کسب‌وکار (`src/config/limits.js`، قابل تغییر با env): اعضا، پلن‌ها، فاکتور در 24 ساعت، فاکتور پرداخت‌نشده، صدور خودکار فعال، اعلان در 24 ساعت، عضو جدید در 24 ساعت. میزان مصرف در تنظیمات دیده می‌شود.

## امکانات دیگر
* یادآوری خودکار پایان اشتراک با اعلان و ایمیل
* پروژه ES Module است، فشرده‌سازی پاسخ‌ها و کش view در production

## امنیت
* محافظت CSRF (بررسی `Sec-Fetch-Site` و `Origin`)
* جلوگیری از NoSQL injection (coerce کردن همه‌ی ورودی‌های query) و ReDoS (escape کردن regex جستجو)
* همه‌ی کوئری‌ها با `user` مالک scope شده‌اند (جلوگیری از IDOR)
* پرداخت اتمیک (جلوگیری از تأیید دوباره‌ی همزمان یک فاکتور)
* ایمن‌سازی CSV در برابر formula injection
* لینک عمومی فاکتور با شناسه‌ی تصادفی (نه ObjectId)
* Rate limit عمومی + محدودکننده‌ی سخت‌گیرانه برای login / register / check-availability
* Helmet (CSP, HSTS, ...) ، کوکی `httpOnly` + `secure` + `sameSite`
* اعتبارسنجی env هنگام اجرا (رد کردن `SESSION_SECRET` ضعیف در production)
* وابستگی‌ها: `npm audit` بدون آسیب‌پذیری

## اجرا

```bash
cp .env.example .env     # مقادیر را پر کنید
npm install
npm run seed             # (اختیاری) داده‌ی نمونه برای دمو
npm run dev
npm test                 # تست‌های واحد (بدون نیاز به دیتابیس)
# تست یکپارچه روی MongoDB واقعی (اختیاری؛ دیتابیس باید موقت باشد و اسمش به _it یا _test ختم شود، چون پاک می‌شود):
INTEGRATION_MONGODB_URI=mongodb://127.0.0.1:27017/faktorito_it npm test
```

مهاجرت پایگاه داده‌ی قدیمی: `npm run backfill:public-ids`

## استقرار (روی همان پروژه‌ی اصلی)
ساختار پوشه‌ها همان پروژه‌ی اصلی است (`app.js`، `src/{config,middleware,models,routes,utils,validators}`، `views`، `public`) و فقط پوشه‌های جدید `src/{services,jobs,realtime,emails}`، `scripts` و `tests` اضافه شده‌اند. شاخه با `origin/main` بدون تداخل مرج می‌شود.

```bash
git merge feat/esm-roles-realtime
npm ci --omit=dev          # نصب production
npm start                  # cross-env NODE_ENV=production node app.js
```
متغیرهای لازم در production: `MONGODB_URI`، `SESSION_SECRET` (حداقل 32 نویسه)، `GMAIL_USER`، `GMAIL_PASSWORD`. اختیاری: `APP_URL`، `LEGAL_*`، `LIMIT_*`. مهاجرت داده‌های قدیمی هنگام بالا آمدن سرور خودکار اجرا می‌شود.

## پرداخت
Faktorito درگاه پرداخت ندارد. پرداخت با کارتخوان، کارت‌به‌کارت یا نقدی انجام می‌شود و صادرکننده وضعیت را ثبت می‌کند (`isPaid`).
